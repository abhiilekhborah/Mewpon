# Phase 7 — local speech and integration research

Verified 25 October 2026. Repository metadata and maintenance timestamps are recorded in `Verification/Phase7/research-metadata.json`. Project claims below are upstream capabilities, not measured Mewpon results. No repository is described as faster than another without a local comparative benchmark. Model licenses are distinct from runtime licenses.

| Project | License / platform | Assessment and decision |
|---|---|---|
| [whisper.cpp](https://github.com/ggml-org/whisper.cpp) | MIT; Apple Silicon, Accelerate, Metal/Core ML options | Selected multilingual file/utterance backend. Verified Homebrew official formula `whisper.cpp` 1.9.5, packaged dependencies, and separately pinned/hash-verified publisher GGML base model. Fixed process argv, local files only, no shell or server. Base upstream memory estimate ~388 MB; actual app measurements are separate. |
| [sherpa-onnx](https://github.com/k2-fsa/sherpa-onnx) | Apache-2.0; macOS ARM64, Swift/C/C++ | Strong candidate for streaming, VAD, keywords and diarization. Model-specific language/licensing/runtime integration still required. Not installed or benchmarked in this milestone; no speed/accuracy comparison invented. |
| [FluidAudio](https://github.com/FluidInference/FluidAudio) | Apache-2.0; native Swift/Core ML | Attractive ASR/TTS/diarization integration; several current models require macOS 15 and modern Swift package traits. Default models may auto-download. Deferred rather than silently changing deployment target or downloading multiple heavy models. |
| [openWakeWord](https://github.com/dscripka/openWakeWord) | Apache-2.0 code; separately licensed models | Dedicated keyword engine candidate. “Hey Mewpon” is a custom phrase requiring a tested model; not falsely represented as an existing pretrained keyword. Current implementation uses explicitly on-device streaming ASR with an exact wake phrase, is opt-in, and is not advertised as a dedicated low-power detector. |
| [Piper](https://github.com/OHF-Voice/piper1-gpl) | Current engine GPL-3.0; voice licenses vary | Fast local engine candidate, but bundling requires reviewing GPL distribution obligations and each voice. Not integrated automatically into the existing app. |
| [Kokoro](https://github.com/hexgrad/kokoro) | Apache-2.0 runtime/model; separate frontend dependencies | Potential higher-quality small local TTS model. Not claimed to support emotional controls. Deferred model/frontend integration while installed macOS voices provide actual zero-download local synthesis. |
| [MLX Audio](https://github.com/Blaizzy/mlx-audio) | MIT code; individual model licenses differ | Apple Silicon optimized, but Python/MLX and multiple model families add memory and packaging work. Do not infer commercial rights or emotional support from the code license. Deferred; not benchmarked. |
| [pyannote.audio](https://github.com/pyannote/pyannote-audio) | MIT toolkit; model access/terms vary | Genuine offline diarization after model acquisition, but common pipelines require gated model access and PyTorch. No account/token or multi-GB models installed silently. Speaker identity remains unknown unless a real source/algorithm or the user assigns a label. |
| [Playwright](https://github.com/microsoft/playwright) | Apache-2.0; macOS | Browser testing/automation candidate. A new managed browser profile cannot inherit existing user accounts; browser binaries and authenticated workflows require explicit setup. Native URL opening and approved page-context extraction remain the minimal supported path. |
| [SQLite](https://github.com/sqlite/sqlite) | Existing system SQLite in the project | Reuse the existing local search architecture. Sensitive meeting transcripts should remain encrypted on disk; use bounded decrypted in-memory search instead of adding an unencrypted transcript index. |

Installed native option: Apple Speech/AVFoundation are proprietary OS frameworks, not open-source dependencies. `requiresOnDeviceRecognition = true` is mandatory, with `supportsOnDeviceRecognition` checked before starting. This Mac reports en-IN and en-US available on-device; hi-IN does not. No cloud fallback is permitted. AVSpeechSynthesisVoice enumerated installed English/Indian English/Hindi voices. Installed voices are used without downloading a second TTS model.

Actual first speech fixture: native Rishi Indian English synthesized “Change to dark mode.” into a nonempty WAV in 441.64 ms; offline Whisper recognized it exactly in 7309.29 ms, including process/model/backend initialization. This is one synthetic fixture, not human-speech WER or a comparative engine benchmark. Bundled engine logging shows ~0.27 s internal processing plus substantial Metal initialization; total command latency must include that startup. Apple streaming is the default for interactive commands, with Whisper used for multilingual files/utterances. Hindi human-speech accuracy and noise tolerance remain unverified.

[Apple on-device recognition](https://developer.apple.com/documentation/speech/sfspeechrecognitionrequest/requiresondevicerecognition), [AVSpeechSynthesizer audio buffers](https://developer.apple.com/documentation/avfaudio/avspeechsynthesizer/write(_:tobuffercallback:)), and [ScreenCaptureKit](https://developer.apple.com/documentation/screencapturekit/capturing-screen-content-in-macos) are the native API references. No screen/system audio is captured merely by opening a workspace.

## Subsequent implementation evidence — 25 October 2026

Offline diarization now uses the official sherpa-onnx v2.0.0 macOS universal no-TTS runtime through a source-built C helper. The release archive matches its publisher SHA-256. CNRS segmentation includes an MIT license; the 3D-Speaker upstream model card declares Apache 2.0. Model artifact hashes are recorded after official HTTPS download, without claiming an independently published digest or an unstated conversion revision. See Verification/Phase7/diarization-provenance.json and embedding-upstream-readme.md.

Primary references: https://k2-fsa.github.io/sherpa/onnx/speaker-diarization/models.html ; https://github.com/k2-fsa/sherpa-onnx/releases/tag/v2.0.0 ; https://github.com/k2-fsa/sherpa-onnx/releases/tag/speaker-segmentation-models ; https://modelscope.cn/models/iic/speech_eres2net_base_sv_zh-cn_3dspeaker_16k/summary .

Explicit online clients use Open-Meteo weather and BBC RSS. Requests are opt-in, bounded, allowlisted and source-attributed; no user account is connected. Official references: https://open-meteo.com/en/docs ; https://open-meteo.com/en/pricing ; https://github.com/open-meteo/open-meteo ; https://feeds.bbci.co.uk/news/world/rss.xml ; https://feeds.bbci.co.uk/sport/rss.xml . Current fixtures establish response parsing, not universal data accuracy or feed reuse rights beyond applicable source terms.

Local translation remains experimental: the installed qwen3:8b passed two meaning fixtures where the 4B Hindi output failed. No model was downloaded for this comparison. No notification, browser or capture live verification is implied by source-level implementation.
